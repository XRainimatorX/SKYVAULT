# Phase 5 回顧

Observation Contract v0.5

這份文件檢討**流程**，不檢討人。所有問題都以「什麼樣的做法讓這件事得以發生」來描述 —— 目標是讓下一個階段不要重蹈，不是追究誰的責任。

寫完不再更新。

---

## 1. 摘要

Phase 5 交付了兩份觀測契約、五種 view、fog of war、confidence、delay、stale 與 partial observation，以及「只看 observation」的 policy 路徑。模擬不變，沒有重工。這是第一個收尾後立刻開設下一個 Phase 的循環（Phase 18 回顧改法 1）。

這一輪值得記下的是：**最重要的缺陷不會讓任何東西失敗。** TAC ANGEL 範例把「敵人打得到我」當成「我打得到敵人」，在每個 scenario 都跑得完、測試全綠。

**核心教訓：介面的第一個使用者要由人讀過，而不只是被執行過；一個「跑得完」的範例只證明介面能被呼叫，不證明它能被正確使用。**

## 3. 做得好的地方

### 先在真實 run 上看輸出，再寫測試

observe 寫完先在 reference 與四個軍事 scenario 上印出每 tick 的 visible / stale / hidden。fog、stale 與 concealment 在真實資料裡都會觸發（Phase 7 回顧：每個規則要有一場真實的 run 證明它會觸發），不是只有手造資料。

### 「拿不到」由結構保證，不由約定保證

observing policy 沒有 decide_action，engine 根本不給它 world。測試在 engine 內部包住 observe，對照每一次它實際收到的歷史檢查 —— 檢查的是 engine 給了什麼，而不是事後重建的近似。

### 兩條歷史路徑互相對照

engine 跑的時候記的歷史與 run 之後從 package 重建的歷史，逐 tick 相同。之後任何一邊改了，另一邊會抓到。

## 4. 出了什麼問題

### 問題 1：範例的射程方向錯誤

known_risks 的 in_range 是「這個敵人打得到我」。範例拿它決定開火。結果：範例只在敵人打得到它時才開火，而且是以敵人的射程判斷。

### 問題 2：自己的預期值算錯兩次

同距離的決勝與 5×5 地圖的覆蓋格數。都是在程式跑出結果後對照規則才確認。

### 問題 3：測試之間的隱性共享狀態

policy registry 是 process 層級的；兩個測試檔各自載入同一個 .py，順序決定誰會紅。

### 問題 4：一個變異讓測試不會結束

缺口計數的 flood fill 不標記已走過的格子時永遠不停。抓得到，但代價是一個被系統終止的 process（Phase 17 也遇過一次）。

---

## 5. 根本原因

### 成因 1：範例只被執行，沒有被當成使用者讀

範例是新介面的第一個使用者。它「跑得完、有攻擊、有移動」就被認為是對的。但執行只驗證了介面能被呼叫；欄位的意義只有在讀的時候才會被檢查。

### 成因 2：預期值用心算，沒有用規則的定義逐步推

同分決勝與覆蓋範圍都有明確的規則，但寫預期值時跳過了逐步套用規則。

### 成因 3：全域 registry 沒有被當成共享狀態

registry 的「同名不同 factory 就拒絕」是刻意的保護，但它讓「載入一個檔案」不是冪等的。

---

## 6. 下一階段要改的事

### 改法 1：新介面的第一個使用者，逐欄讀一次

寫完範例或第一個呼叫端後，對每個它讀的欄位問「這個欄位的意思是什麼、我用它做什麼」。Phase 6 的外部 agent 協定適用。

### 改法 2：有規則的預期值，寫出推導

測試裡的精確預期值旁邊用一行註解寫出怎麼來的（例如「三格、每 tick 兩格：兩 tick」）。寫不出來就是還沒推。

### 改法 3：會改全域狀態的測試，先檢查再改

registry 這類 process 層級的狀態，測試要能在任何順序下執行；推送前至少跑一次全套（不只單一檔案）。

### 改法 4：迴圈類的程式，變異腳本加上逾時

mutlib 已有 300 秒的逾時；記錄「不會結束」為一種結果，而不是紅或綠。

---

## 7. 沒有結論的一項

**觀測層是否該取代軍事 pack 的感測。**

軍事 baseline policy 讓每個單位用自己的感測決定，觀測層是整個陣營共享。兩者都合理：前者模擬沒有通訊的小隊，後者模擬有共享圖像的指揮。Formal Spec 沒有說哪一種是 SKYVAULT 的預設。若改成共享感測，軍事 run 的結果會改變（reference trace 不受影響，但軍事的漂移測試會）。留給 Phase 6（Actor / Agent Layer）在定義 agent 的感知時決定，可能需要讓 observer profile 指定 `sensing: individual | shared`。

---

## 8. 一句話

> Phase 5 讓每個系統只看到它該看到的世界，而它最該記住的一課是：範例在每個 scenario 都跑得完，卻把「敵人打得到我」讀成了「我打得到敵人」—— 跑得完不等於用得對。
