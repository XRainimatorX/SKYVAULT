# Phase 23 回顧

## 1. 起因

使用者問「係數是手調的」是什麼意思，接著要求「search it」：用真實資料校準信息環境、災害、重建三個城市模型的係數。

## 2. 做得好的

- 先量再改：開設時就確認了研究和模型單位對不上，所以改做以型態定錨，沒有硬擬合出假精確的數字。
- 每個係數都標了可信度，assumed 佔 23 / 29，如實寫出來。
- 敏感度分析找出真正會翻轉結論的係數，它們不是原本以為最不確定的那批。
- 型態測試重新跑模型，而不是只比對數字；敏感度報告有一條「過期就失敗」的守護。

## 3. 做得不好的

- 一開始派子代理去讀論文全文，結果全部被網路擋下，浪費一輪。應該先用一個網址試網路。
- 全套測試在改版本號之前就開始跑，版本測試因此誤報。版本號應該在開跑前改，或跑完後再改。
- 跑 CI 的城市步驟時覆蓋了不屬於城市的 output 檔，要手動還原。

## 4. 根因

- 模型的抽象單位（0–100 的分數）是 Phase 14 為了可解釋性選的，從沒考慮過要對照真實資料。
- `industry_up` 這類係數一個數字代表兩種過程，校準時才發現。

## 5. 學到的

- 校準前，先問研究給的量和模型的量是不是同一種東西。不是的話就標為 assumed，不要硬換算。
- 一個係數若對應到研究裡的兩種現象，先把它拆開再定錨。
- 敏感度分析要在找資料之前做：它決定先找哪份資料。

## 6. 下一個 Phase 的改法

- 若要繼續校準，先找 `recovery.administer` 和 `order.dark` 的資料，例如災後行政服務恢復的速度、停電與治安的城市級資料。
- 網路允許時，讀全文核對六個 anchored / derived 係數。
- 敏感度分析若要量係數之間的交互作用，可以改用 Morris 法或 Sobol 法。
